# Implementation decisions

This file records implementation choices beyond the owner's decisions in the PRD.

1. **Go 1.25 minimum.** The official MCP SDK pinned here is v1.8.0 and its own module requires Go 1.25. The module and Docker builder therefore use Go 1.25 rather than the PRD's illustrative Go 1.23 builder. SQLite uses the specified CGO drivers and the mandatory `sqlite_fts5` build tag.
2. **CGO runtime.** The binary links SQLite and sqlite-vec into the executable but uses glibc. The Debian runtime follows the detailed Docker requirements; the broad “static binary” goal does not mean a fully static libc build. The build stage installs SQLite headers for sqlite-vec; the runtime does not require a SQLite executable or extension file.
3. **Health exception.** `/healthz` is unauthenticated as explicitly required by the operations section, despite the general “every path” authentication wording. All other paths, including unknown routes and MCP, require a token.
4. **Markdown is the source; SQL serves reads.** Only add and patch touch Markdown (patch reads just its target file). Get/latest/search/similar read the derived index (`ORDER BY date DESC LIMIT ?` for latest), so external Markdown edits need normalize before any read reflects them. Startup rebuilds the index from Markdown when `diary.db` is new or the embedding status is stale; an embedding failure there aborts startup. A malformed Markdown file aborts a rebuild rather than silently disappearing. Memory reads diaries only through the diary service, never through files or `diary.db`.
5. **Atomic files and incremental indexes.** Markdown is written to a temporary sibling, synced, then renamed. Add/patch then upsert only that entry's rows. A failed embedding leaves the entry indexed without a vector (similar skips it, the dream still runs) until normalize backfills it; patch re-embeds only when the summary changes. Normalize rebuilds the derived tables in one transaction while reusing embeddings for unchanged file paths and summaries. Diary ids are internal and can change on normalization.
6. **Vector dimensions and ordering.** Existing reused vectors determine dimensions; otherwise the first provider result does, with the configured fallback for an empty index. Mixed dimensions are rejected. sqlite-vec only supports ascending distance order, so the selected nearest results are reversed in Go to put the most similar entry last.
7. **Bounded-library executor.** Each memory transaction reads a consistent library, applies validated actions in order, runs cleanup and post-checks, and persists the resulting bounded library in that same transaction. This makes rollback and agent restrictions share one path. Entry ids use SQLite's persistent high-water mark; normal deletion never reuses ids. Restore resets the sequence to the restored maximum.
8. **Optional existing-topic kind.** Add may omit kind for an existing topic, matching the REST/MCP signatures; an explicitly supplied mismatching kind fails. New non-core topics require kind. Topic resolution is exact name, folded name, then folded alias.
9. **Snapshots are commit side effects.** Worker-controlled changes snapshot synchronously after commit. An I/O failure is surfaced and logged, but cannot undo an already committed SQL transaction. A later normalize can retry the snapshot. Snapshot names use UTC plus numeric collision suffixes, sorted numerically within the same second. Restore validates the selected snapshot before the safety snapshot, so “latest” cannot accidentally select the just-created safety backup.
10. **Restore preserves history across configuration changes.** Restore validates structural integrity, references, kinds, provenance and dates; it does not reject old entries merely because current configured caps were lowered. Normalize can then compact over-limit libraries. Startup restore does not overwrite a corrupt existing database: automatic restore is specifically for a missing database.
11. **Worker ownership.** A mutex reserves memory writes/jobs before acceptance. Dreams coalesce into one pending flag, and queued work wakes after external writes release the mutex. Read transactions remain independent. Manual normalize/init/restore are accepted as background work only when the mutex is available. Jobs retain their last 20 outcomes in memory.
12. **MCP transport and validation.** The official streamable HTTP handler runs statelessly. Tool inputs are checked against each tool's explicit fields/types before decoding, rather than relying on low-level SDK registration to validate them. The application's host/origin allow-lists are authoritative; the SDK's separate localhost heuristic is disabled behind that middleware so a configured reverse-proxy hostname works. Tool failures use the same error JSON as REST.
13. **Provider calls.** Embedding batch output order follows provider indexes, with duplicate indexes and inconsistent dimensions rejected. LLM validation retries include the rejected reply and exact validation error; transport retries resend the original messages with cancellable exponential delay. Provider errors do not put raw provider bodies in client responses.
14. **Configuration precedence.** Fixed secret aliases win over long aliases at equal source priority, but a process-level long alias still beats a fixed alias loaded from `.env`. Prompt names are configuration-only. Logs redact secret values; debug prompts and replies are intentionally opt-in and can contain private diary content.
15. **Interface limits.** REST search limits are bounded to 10,000 results to reject unreasonable integer inputs; the configured default remains 20. Memory init uses entry-count replay rather than calendar arithmetic and caps recent at 365. Timestamps use UTC, while diary future checks and normal dream dates use the configured timezone.
16. **Reference availability and anonymity.** The predecessor repository search returned no accessible source. Compatibility is implemented against the PRD's explicit Markdown and API contracts and covered with legacy-format fixtures; undocumented predecessor behavior is not claimed as verified. New docs, prompts and fixtures use neutral roles. The specified public module path and product name are retained; the supplied PRD remains untouched, including its original examples.
17. **Local development environment.** A C compiler and SQLite development headers are required. `make check` supplies the FTS5 build tag and runs the race-enabled suite and vet. Fake providers listen only on local test ports; no tests use real credentials or external LLM/embedding services.
